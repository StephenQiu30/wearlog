# 用户账户与认证产品规格 (PRD - Woo 1:1 复刻版)

## 1. 摘要与核心 SLA 指标

本规格确立“Woo / Wearlog 用户账户、身份认证与多租户资产隔离体系”的产品功能验收标准，依据 [REQ-03](../requirement/03-用户账户与认证.md) 与 [DES-03](../design/03-用户账户与认证.md)。

### 核心 SLA 与安全指标
1. **身份认证时效**：常规会话读取与校验 **P95 ≤ 50ms**；
2. **密码存储安全**：强制 bcrypt 哈希（cost ≥ 12），明文 100% 不落盘；
3. **注销物理清扫彻底性**：账户注销后，所有 MinIO 物理媒体资产及 PostgreSQL 业务记录在 **≤ 24 小时** 内被彻底清扫物理粉碎；
4. **租户资产横向越权率**：**0%**（未授权跨用户资源访问统一返回 404）。

## 2. 界面与交互体验规范

```text
+----------------------------------------------------------------------------------------------------+
| WOO                                 [ RUNWAY | WARDROBE ]                                (🔍) (+) (☰)|
+-------------------+---------------------------------------------------------+----------------------+
|                   |                                                         | PROFILE OVERVIEW     |

| (走秀台与数字衣橱) |                     [ 页面主内容 ]                      | 于是用户             |

|                   |                                                         | - Chrome on Mac (现) |
|                   |                                                         |                      |

+-------------------+---------------------------------------------------------+----------------------+
```

1. **登录/注册表单 (`/login`, `/register`)**：
   - 极简居中卡片，仅包含邮箱与密码两个主输入框，支持显示密码切换；
   - 字段错误就地提示（如邮箱格式、密码长度不足 12 字节），无冗余弹窗阻断；
2. **账户管理与个人主页 (`/account`)**：
   - 个人名片展示（头像、昵称、唯一 Handle、简介）；
   - 活跃会话列表及单点注销按钮；
   - 肖像确权声明开关；
   - 账户注销危险操作区域（需二次弹窗确认）。

## 3. 验收条件 (Acceptance Criteria)

| 编号 | 对应需求 | Given 前置条件 | When 触发操作 | Then 预期结果 (客观可验证) |
| :--- | :--- | :--- | :--- | :--- |
| **AC-01** | ACC-FR-01、ACC-NFR-01 | 用户访问 `/register` 页面 | 输入合法邮箱与 12~72 字节密码并提交 | 成功创建账户并自动登录，响应中包含 HttpOnly Cookie，页面跳转至主站 |
| **AC-02** | ACC-FR-01 | 数据库已存在某邮箱 | 其他人尝试用该邮箱再次注册 | 明确拦截并返回 409 Conflict，提示该邮箱已被注册，密码不被明文记录 |
| **AC-03** | ACC-FR-01 | 用户访问 `/login` 页面 | 输入错误密码尝试登录 | 统一返回 401 模糊错误（“邮箱或密码错误”），禁止提示“该邮箱不存在”或“密码错误” |
| **AC-04** | ACC-FR-02、ACC-NFR-02 | 用户成功登录系统 | 浏览器端检查网络包与 Cookie 存储 | Cookie 标记为 `HttpOnly`、`SameSite=Strict`，JavaScript 脚本无法通过 `document.cookie` 读取 |
| **AC-05** | ACC-FR-03 | 用户在 `/account` 编辑资料 | 输入 3~30 位小写 Handle、新昵称与简介并保存 | 提交带 `expected_revision`；保存成功后版本号自增；Handle 冲突时返回 409 且提示更换 |
| **AC-06** | ACC-FR-04 | 用户 A 拥有穿搭 Look `L-1` | 用户 B 登录后直接尝试请求 `GET /orbit/looks/L-1` | 后端强制携带 `WHERE user_id = ?`，查询不到直接返回 404 Not Found，杜绝越权 |
| **AC-07** | ACC-FR-05 | 前端渲染模特图与精灵图 | 检查网络图片请求链接 | 统一使用带有时效性签名参数的 MinIO URL（过期时间 1 小时），禁止直接使用未验签静态直链 |
| **AC-08** | ACC-FR-06 | 用户未签署成年声明 | 尝试点击“虚拟试穿”或“生成 360°” | 弹出模态窗口提示签署《本人与成年肖像声明》；用户点击确认后方可继续执行生成管道 |
| **AC-09** | ACC-FR-07 | 用户在设置中提交注销申请 | 二次确认并提交注销 | 立即清除 Session Cookie 并退出登录；响应交付一次性 43 位收据 Token；后台异步彻底清扫媒体与数据库 |
| **AC-10** | ACC-FR-08 | 用户在设置中点击“导出全部数据” | 提交导出申请 | 后端启动异步导出任务，完成后生成加密 ZIP 包下载链接，7 天有效 |

## 4. 业务数据模型与关键常量

```go
type User struct {
    ID            string        // UUID v4
    Email         string        // RFC 5322, 小写
    DisplayName   string        // 1-80 字符
    Status        AccountStatus // active, suspended, deleting
    Role          AccountRole   // user, moderator, admin
    Revision      int           // 乐观锁版本号
    CreatedAt     time.Time
    UpdatedAt     time.Time
}

type PublicProfile struct {
    Handle      string  // 唯一个性标识, ^[a-z0-9_]{3,30}$
    DisplayName string  // 显示昵称
    Bio         *string // 最多 300 字符
    AvatarURL   *string // 签名后的头像地址
    Revision    int
}
```
