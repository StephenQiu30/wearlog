# 用户账户与认证需求规格 (Woo 1:1 复刻版)

## 1. 用户问题与核心目标

在数字化穿搭与个人衣橱产品中，用户的穿搭相册、衣物单品与日记属于**高度私密资产**。系统必须提供既简便又坚固的账户体系：

1. **极简低摩擦的身份认证**：采用行业最成熟、最通用的 **“邮箱 + 强密码”** 模式，拒绝繁杂的手机短信与第三方授权依赖；
2. **安全防盗号的会话管理**：采用同源 `HttpOnly` + `SameSite=Strict` Cookie 机制，从底层拦截浏览器端 XSS 恶意脚本盗取 Token 的风险；
3. **唯一的时尚主页名片**：为每位用户提供全局唯一的 Handle（如 `@then_style`），支持设定昵称、头像与个性简介；
4. **穿搭资产的严格租户物理隔离**：确保用户的穿搭时光轴（Looks）、数字衣橱（Wardrobe）单品在数据库与对象存储层面 100% 物理隔离，杜绝横向越权（IDOR）；
5. **数据主权与彻底被遗忘权 (GDPR)**：提供用户自主注销账户并彻底物理清扫所有云端图片与记录的合法主权，并交付一次性可验证凭证收据。

### 明确排除的非目标 (Explicit Non-Goals)
- ❌ **坚决不录入任何身材身体数据**：不采集身高、体重、三围、体脂率、骨架体型分类（降低心理门槛与数据安全包袱）；
- ❌ **不做手机短信验证码与第三方扫码登录**（MVP 阶段保持纯粹极简，避免外部短信通道成本与风控拦截）；
- ❌ **不承担试穿模特逻辑**（模特的渲染、预置与切换归入独立的《04 预置虚拟模特与试穿人像》主题）。

## 2. 业务功能需求范围

### 2.1 账户凭据与注册登录
- **登录邮箱**：格式符合 RFC 5322，长度在 3~254 字符之间，服务端落盘前强制转小写，全局唯一；
- **用户密码**：
  - 客户端提交后，服务端严格按 **12 ~ 72 个 UTF-8 字节** 进行长度校验；
  - 采用 **bcrypt (cost ≥ 12)** 算法进行单向不可逆加密，明文密码绝对禁止落盘或记录日志；
  - 登录失败时统一响应模糊的 `401 Unauthorized`（"邮箱或密码错误"），严禁暴露“该邮箱尚未注册”或“密码错误”等利于撞库探测的信息。
- **密码重置与安全找回**：
  - 用户发起重置后，服务端生成 15 分钟有效的随机高熵 Challenge Token；
  - 邮件安全下发，用户提交新密码完成修改后，立即强制失效原账号的所有活跃会话。

### 2.2 安全会话机制 (Session Lifecycle)
- **同源 Cookie 机制**：
  - 登录成功后，服务端在 Response Header 通过 `Set-Cookie` 交付名为 `then_session` 的凭据；
  - 强制标记属性：`HttpOnly`（禁止前端 JS 脚本读取，杜绝 XSS）、`Secure`（生产环境强制 HTTPS 传输）、`SameSite=Strict`（拦截跨站 CSRF 伪造）；
- **会话查看与下线**：
  - 提供 `/account/sessions` 接口，支持查看当前账号在所有设备的登录状态（创建时间、过期时间、是否为当前设备）；
  - 支持单点退出当前会话，或一键清除其他设备会话。

### 2.3 个人主页与时尚名片 (Public Profile)
- **唯一个性域名 Handle**：
  - 正则约束：`^[a-z0-9_]{3,30}$`（只能包含小写字母、数字与下划线）；
  - 作为未来个人穿搭画报外链与个人主页的标识符（如 `/profile/then_style`）；
- **显示昵称 (DisplayName)**：
  - 长度限制 1 ~ 80 个字符，支持中英文、空格与 Emoji；
- **时尚简介 (Bio)**：
  - 最多 300 字符，用于阐述个人的穿搭理念与审美偏好；
- **并发冲突防护 (Revision Lock)**：
  - 提交更新时强制传递 `expected_revision`；若并发检测到版本已被其他端修改，返回 `409 Conflict` 保护数据不被覆盖。

### 2.4 资产所有权与多租户隔离 (Tenant Isolation)
- **SQL 层面强制隔离**：
  - 用户的穿搭时光轴（Looks）、数字衣橱单品（Wardrobe Items）、穿搭计划（Plans）与日记（Diary）底层表结构均有 `user_id` 外键索引；
  - 业务查询强制自动拼装 `WHERE user_id = ?` 条件；
  - 若用户尝试用伪造的 UUID 访问他人私有单品或穿搭，系统统一返回 `404 Not Found`（不返回 403，避免证实该资源的存在性）。
- **MinIO 图像防盗链与短期签名**：
  - 用户上传的原图、抠图与精灵图保存在私有存储桶；
  - 客户端获取的所有图片 URL 均为带有时效性签名参数的访问链接（默认有效时长 1 小时），禁止向互联网暴露公网无鉴权直链。

### 2.5 隐私合规与数据主权 (Privacy & GDPR Compliance)
- **肖像合规确认声明 (`self-adult-v1`)**：
  - 首次使用换装或生成功能前，必须弹窗勾选确认《本人且成年合规声明》；
  - 用户可随时在设置面板中撤回该声明，撤回后即刻冻结 AI 生成功能；
- **账户彻底注销与异步粉碎清扫**：
  - 用户确认注销后，当前会话即刻失效，账号状态变更为 `deleting`；
  - 后台异步 Outbox 任务开始彻底清扫：
    1. 物理删除 MinIO 中的所有图片资产；
    2. 物理删除 PostgreSQL 中的用户行及关联的全部业务记录；
  - 交付一次性 43 字符的收据 Token，用户在未登录状态下可凭该 Token 追踪清扫进度；完成后收据保留 7 天自动作废。
- **个人全量数据打包导出**：
  - 提供数据自由迁移权，支持用户一键申请“导出我的全部数据”；
  - 异步将用户的衣橱数据、穿搭画报打包成加密 ZIP 文件，生成 7 天内有效的临时安全下载地址。

## 3. 功能与非功能需求表

| :--- | :--- | :--- | :--- | :--- |
| **ACC-FR-01** | 认证 | **邮箱与密码注册登录**<br>支持邮箱注册，校验密码 12~72 字节，bcrypt 单向哈希存储 | 邮箱已被注册返回 409；密码不符合规范返回 400 | 邮箱唯一；密码安全存储；登录失败统一 401 模糊报错防探测 |
| **ACC-FR-02** | 会话 | **HttpOnly Cookie 安全会话**<br>服务端通过 Set-Cookie 交付 `then_session`；支持查看与撤回其他设备会话 | 会话过期自动清除；跨域请求拦截 | 客户端无法通过 `document.cookie` 窃取凭据；注销立即失效 |
| **ACC-FR-03** | 名片 | **全局唯一 Handle 与个人名片**<br>支持维护 3~30 位小写 Handle、显示昵称、300 字简介与头像上传 | Handle 重复返回 409；非法字符拦截 | Handle 全局唯一；更新带 `expected_revision` 乐观锁防冲突 |
| **ACC-FR-04** | 隔离 | **穿搭时光轴与衣橱资产租户隔离**<br>Looks 与 Wardrobe 单品严格隔离在当前已认证用户 ID 下 | 试图越权访问非本人资源 ID | 越权访问统一返回 404，杜绝水平越权漏洞 (IDOR) |
| **ACC-FR-05** | 安全 | **私有媒体防盗链与短期签名访问**<br>图像资产存于 MinIO 私有桶，通过 1 小时有效期签名 URL 访问 | 签名过期、外链恶意盗刷 | 禁止永久公开访问，有效防盗链与防盗刷 |
| **ACC-FR-06** | 合规 | **成年与肖像权合规声明 (`self-adult-v1`)**<br>首次使用 AI 生成前需主动勾选肖像与成年确认 | 未确认即发起生成请求 | 未确认拦截并弹窗引导；撤回即刻冻结 AI 功能 |
| **ACC-FR-07** | 注销 | **GDPR 彻底物理注销与异步清扫**<br>申请注销后立刻注销 Cookie，后台异步物理抹除所有云端文件与数据库行 | 注销后被他人恶意查询 | 交付 43 位一次性收据；对象存储与数据库物理清扫 100% 彻底 |
| **ACC-FR-08** | 导出 | **个人资产一键打包导出**<br>用户申请导出个人数据，后端异步打包衣橱与搭配记录为 ZIP | 大数据量导出超时 | 异步任务处理，提供 7 天有效的临时下载链接 |
| **ACC-NFR-01**| 安全 | **密码不可逆存储与传输强加密**<br>密码采用 bcrypt (cost ≥ 12) 哈希，网络通信强制 TLS 1.3 | 密码明文泄漏风险 | 密码永不落盘明文，会话 Cookie 防截获 |
| **ACC-NFR-02**| 性能 | **账户读写低时延**<br>常规会话核对、资料获取与资料更新响应指标 | 页面频繁认证与跳转 | **P95 ≤ 50ms**（PostgreSQL 索引 + Redis 缓存） |
| **ACC-NFR-03**| 安全 | **日志敏感数据脱敏**<br>全链路日志与错误堆栈中严格过滤敏感字段 | 错误排查与分析日志 | 严禁在日志中记录密码、Token 或完整签名密钥 |
