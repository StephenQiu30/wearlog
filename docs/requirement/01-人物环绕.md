# 人物环绕与立体数字衣橱需求规格 (Woo 1:1 复刻版)

## 1. 用户问题与核心目标

对标 **“Woo 立体数字衣橱”**，全面解决用户“衣橱杂乱、试穿费时、买衣不知道怎么搭”的痛点：
1. **唤醒相册穿搭**：将单张全身穿搭照片转化为**可 360° 拖拽查看的高保真立体形象**；
2. **自动化单品归档**：智能识别整套搭配中的外套、上装、下装、鞋履与配饰，分析适合的季节、温度区间与穿搭风格，一键收纳进数字衣橱；
3. **保持原有姿势的虚拟换装**：在衣橱（或外部商品）挑选衣服，Woo 能将其直接穿到照片上，**严格保持原有姿态、身材比例与五官面部**，生成逼真试穿效果。

### 刚性技术与算力约束
- **零自建 GPU 算力**：团队不自行部署或维护任何显卡模型服务，全量功能通过**“成熟商用/Serverless API + 端侧轻量 WebAssembly”**实现；
- **前后端分工基线**：
  - 前端采用 **Vercel (Next.js) + shadcn/ui + Radix UI + Tailwind CSS v4 + ESLint + Prettier + Axios + `@umijs/openapi`**；
  - 后端采用 **`/backend` (Go + Gin/Huma + GORM + PostgreSQL + MinIO)**，负责与第三方 AI API 通信并输出 `/openapi.json`。

## 2. 业务功能范围与边界

### 2.1 核心覆盖范围
1. **照片输入与标准化**：单张清晰正向全身照，头脚完整，脚底接地基线自动锁定；
2. **端侧瞬时 2.5D 视差**：利用前端 `onnxruntime-web` 在本地计算深度图，300ms 内提供微立体视差，消除网络等待；
3. **单品自动解构与分析**：
   - 提取外套、上装、下装、鞋履、配饰白底图，展示于底部横滑单品 Dock；
   - 提取适宜季节（春/夏/秋/冬）、温标区间（如 15℃~22℃）及风格标签；
4. **原生姿态虚拟试穿（快道）**：点选单品后，2.5 秒内完成 2D 原生姿势换装，姿态与面部零漂移；
5. **按需 360° 环绕生成（慢道）**：用户确认搭配后，按需生成 16 关键帧 WebP Sprite Sheet，前端 Canvas 2D 满帧流畅旋转；
6. **电商增量扩展**：支持传入电商白底图或商品链接进行一键试穿。

### 2.2 严格排除的过度设计
- 不做端上 3D 几何建模（Mesh/GLB/骨骼解算/实时物理布料）；
- 不做手势高频 Seek MP4 视频；
- 不自建自托管 PyTorch / ComfyUI 集群服务。

## 3. 功能与非功能需求表

| 编号 | 需求名称 | 行为与实现机制 | 场景 / 异常处理 | 成功指标 / 验收方式 |
| --- | --- | --- | --- | --- |
| **FR-01** | 全身照输入与基线定标 | 接收单张全身穿搭照，校验头脚完整度，统一脚底接地基线 | 遮挡过重、半身照提示重新上传 | 正确识别单人全身，构图统一居中 |
| **FR-02** | 端侧 2.5D 深度视差微动 | 前端利用 `onnxruntime-web` 本地推算深度图，驱动 WebGL 视差着色器 | 移动端陀螺仪或手指轻微晃动 | **0 算力成本，P95 ≤ 300ms**，首屏秒级立体反馈 |
| **FR-03** | 穿搭季节与单品解构 | `/backend` 调用 Gemini 2.0 Flash 提取季节温标风格；调用 Fal.ai BiRefNet/SAM 2 拆解单品白底图 | 复杂花纹背景、多件衣服重叠 | 准确识别品类，单品进入底部 Dock，打标时间 ≤ 1.5s |
| **FR-04** | 数字衣橱单品 Dock | 展台底部横滑抽屉呈现拆解单品，支持“收藏进衣橱”与“点击试穿” | 单品数量 1~8 件 | 点击单品流畅展开，支持单选与分类切换 |
| **FR-05** | 原生姿态 2D 试穿 (快道) | 选中单品后，`/backend` 调用 FASHN.ai / Fal.ai CatVTON API 执行换装 | 试穿失败或用户取消 | **P95 ≤ 2.5s**，严格保持原图五官、发型与站立姿势 |
| **FR-06** | 按需生成 16 关键帧 360° | 用户满意当前 Look 点击“生成 360°”，`/backend` 调用 Fal.ai SV3D/Era3D 生成 16 视角并拼装为 WebP Sprite Sheet | 生成超时或单次失败 | **0° 强绑定原图**，首尾接缝无感知跳动，超时熔断线 25s |
| **FR-07** | Canvas 2D 帧拖动浏览器 | 前端 Canvas 2D 监听 Touch 水平滑动，动态映射 Sprite Sheet 切片 UV | 高频反向拖拽、松手停留 | **稳定 60fps 丝滑拖拽**，显存常驻 ≤ 15MB，无丢帧白屏 |
| **FR-08** | 电商外链/单品图扩展 | 支持上传外部商品图或解析电商链接提取衣服进行试穿 | 外部图片带背景杂质 | 自动抠除杂质背景转化为标准单品试穿源 |
| **NFR-01** | 视觉真实感与服帖度 | 正面换装及各角度过渡区域保持面料质感、光影衰减与真实褶皱 | 复杂图案印花 | 无明显塑料感、无融手穿模，视觉质量符合时尚影棚要求 |
| **NFR-02** | 闭环接缝无缝性 | 0° 视角与 360° 旋转交界处过渡完全平滑 | 在接缝处来回拖拽 | 0° 视角误差低于肉眼感知门槛，无闪烁跳帧 |
| **NFR-03** | 端侧性能与内存预算 | 采用 WebP Sprite Sheet (4×4 矩阵)，禁止解压多图导致内存暴涨 | 连续切换多套搭配 | 显存占用 ≤ 15MB，离开页面纹理立即回收 |
| **NFR-04** | 成本控制与零自建 GPU | 核心算力完全依托成熟云端 API，单用户单次体验综合成本可控 | 算力空闲与洪峰 | 服务器空闲时 GPU 账单为 **0 元**，单次体验总成本 ≤ 0.6 元 |
| **NFR-05** | 接口契约一致性 | 后端 Huma 自动生成 `/openapi.json`，前端通过 `npm run openapi` 自动同步 | 接口字段变更 | 前后端 TypeScript 类型 100% 编译期校验，无手工重复定义 |
| **NFR-06** | 隐私与数据隔离 | 用户原图、人像档案与衣橱单品严格按账户物理隔离 | 会话过期、越权访问 | 私有 URL 需验签访问，日志中不打印 API Key 或敏感信息 |
