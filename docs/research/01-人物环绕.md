# 人物环绕：Woo 照片质感、拖动效果与真实实现求证

## 1. 研究目标与采用边界

为 [REQ-01 人物环绕](../requirement/01-人物环绕.md) revision 2 提供依据。用户于 2026-10-24 明确：“接近 Woo 的照片质感与拖动效果是设计的首要目标；当前代码不可靠，不作为本次方案依据。” 并在 2026-10-29 进一步要求对 Woo 视频及评论区反馈进行深度求证，去除过度设计，确保技术选型能真实落地。

本研究穿透分析公开视频、作者直接披露的一手证据（X 平台 @LerSentAI）、抖音平台（`v.douyin.com/TiHhQQmve0w`）互动反馈，以及虚拟试穿（VTON）和多视角生成的业界最新工程实践。结论旨在建立**端到端可落地、低延迟、可控成本**的工程闭环，坚决剔除未经实测的虚幻三维建模与 MP4 手势 Seek 等高风险陷阱。

## 4. 人物、单品与素材生产管线设计

### 4.1 核心主线：分级渐进式体验 (Progressive Pipeline)

```
[用户上传全身照]
       │
       ├─► (0.3s) Depth-Anything-V2 ──► 2.5D 视差着色器 (手势即刻微动，消除等待感)
       │
       ├─► (1.5s) SAM 2 + Gemini 2.0 ──► 单品精准解构 (外套/裤/鞋) + 季节/风格结构化标签
       │
       └─► (按需 3~6s) Era3D / SV3D ──► 16 正交关键角度 ──► WebP Sprite Sheet (360° 丝滑旋转)
```

1. **Stage 0 (0~300ms)：2.5D 深度视差层（即时立体反馈）**
   * 采用轻量级 `Depth-Anything-V2-Small`，输出单图深度图；
   * 前端使用 Canvas/WebGL 进行网格微偏移微动。用户手指触摸屏幕瞬间，人物立刻产生微立体倾斜反馈，彻底消灭黑盒等待。
2. **Stage 1 (1~2s)：单品解构与风格分析（Fashion Parsing & Tagging）**
   * **分割**：`Grounding DINO + SAM 2` 自动分割出外套、上衣、下装、鞋子、配饰；
   * **遮挡补全**：手臂或包带遮挡部位，使用轻量 Inpainting 模型（如 LaMa）进行织物纹理补全，输出规整白底单品图；
   * **打标**：`Gemini 2.0 Flash` 输出季节（春/夏/秋/冬、温标范围）与风格标签 JSON。
3. **Stage 2 (3~6s)：稀疏正交关键帧生成（360° 旋转）**
   * 采用定向多视角扩散模型（如 Era3D / SV3D-Light），固定 16 个水平正交视角（0°, 22.5°, 45°...）；
   * **0° 视角强绑定为原图**：以用户输入的原始照片为绝对几何锚点，数学上保证首尾旋转 360 度严丝合缝，彻底消除跳帧。

## 5. 播放与端侧渲染：摒弃 MP4 Seek，锁定 Sprite Sheet

### 5.1 为什么必须放弃 MP4 Seek
实测表明，在 iOS WebKit/Safari 与 Android WebView 中，对 `<video>` 频繁触发 `currentTime = x` 会引发微线程锁死、关键帧解码排队（Drop frames）和画面发黑。压制为 All-Intra 虽能缓解但文件体积会膨胀 5~8 倍。

### 5.2 推荐方案：WebP Sprite Sheet + Canvas 2D
* **组织形式**：将 16 张 768×1024 关键帧拼成一张 4×4 的网格大图（WebP 格式，带压缩后体积仅约 800KB~1.2MB）。
* **渲染原理**：前端单次加载大图，通过 Canvas `drawImage` 的源切片参数（sx, sy, sWidth, sHeight）根据水平手势位移实时切换。
* **优势**：
  * **内存极低**：单图解码常驻显存仅约 12MB；
  * **60fps 绝对稳定**：纯内存纹理绘制，无网络 I/O 与视频解码调度抖动；
  * **无缝反向与停顿**：完全由代码指针控制，手指停即画面停，完全消除惯性延迟。

## 6. 虚拟换装 (VTO)：动静解耦机制

* **高频试穿走 2D 快道**：用户从衣橱挑选新衣物时，仅调用 2D 换装引擎（**CatVTON / IDM-VTON**）。单次推理 1.5 秒，成本仅数分钱。生成的新 Look 立即附带 2.5D 深度视差。
* **低频环绕走按需慢道**：用户确认喜欢该搭配并点击“生成 360°”后，才向后端提交 16 关键帧的计算任务。
* **支持外部单品输入**：数据合同原生支持粘贴外部电商主图或商品链接，经无头抓取与 SAM 2 抠图后成为数字衣橱的“心愿单单品”，直接穿到用户身上。

## 7. 结论与后续验证重点

1. 确认摒弃三维网格建模与 MP4 手势 Seek 两项过度设计；
2. 锁定“**2.5D 深度即时视差 + 2D 极速试穿 + 16 关键帧 Sprite Sheet 360° 环绕**”的核心三级架构；
