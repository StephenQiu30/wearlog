# 人物环绕与立体数字衣橱：Woo 1:1 复刻与纯 API 架构技术调研

## 1. 研究目标与核心边界

为 [REQ-01 人物环绕](../requirement/01-人物环绕.md) revision 3 提供依据。2026-10-29 确认明确约束：
1. **业务目标**：1:1 完全复刻 Woo 立体数字衣橱的核心体验（单张全身照输入 $\rightarrow$ 360° 可拖动立体形象 $\rightarrow$ 季节风格温标分析 $\rightarrow$ 自动拆解单品进衣橱 $\rightarrow$ 保持原有姿势的虚拟换装）；
2. **算力与工程边界**：**不自建或自行部署模型，团队无独立 GPU 运维算力**。必须采用**“云端成熟商业/Serverless API + 端侧轻量 WebAssembly 计算”**模式；
3. **技术栈与规范边界**：
   - **前端**：Vercel (Next.js) + shadcn/ui + Radix UI + Tailwind CSS v4 + ESLint + Prettier + Axios + `@umijs/openapi` (`openapi2ts`) + Canvas 2D + `onnxruntime-web`；
   - **后端**：`wearlog-server/backend`（Go + Gin/Huma + GORM + PostgreSQL + MinIO），作为安全的 AI API 聚合网关，向前端输出 `/openapi.json`。

## 3. 纯 API 落地选型矩阵（零自建 GPU 算力）

各模块完全采用成熟的开箱即用 API，无需配置任何 CUDA 环境或显卡服务器：

| 业务模块 | 推荐开箱即用 API | 调用方式与技术指标 | 单次调用成本与耗时 | 选型理由 |
| :--- | :--- | :--- | :--- | :--- |
| **穿搭分析与季节打标** | **Google Gemini 2.0 Flash API** | `/backend` 直接通过 REST API 发送照片，开启 `response_schema` 强制结构化输出 JSON | **$0.0001 (约 0.0007 元)**<br>耗时 **≤ 800ms** | 速度最快、价格最便宜的多模态视觉大模型，打标精准。 |
| **单品解构与背景剥离** | **Fal.ai BiRefNet / SAM 2 API**<br>(或 Photoroom API) | `/backend` 调取 Serverless 端点，输入原图，自动抠出外套/裤/鞋并去背景输出透明 PNG | **$0.003 ~ $0.005 (约 0.02~0.03 元)**<br>耗时 **~300ms** | 边缘羽化自然，免除自建分割推理模型。 |
| **2.5D 深度视差微动** | **端侧 onnxruntime-web 本地计算** | 前端加载 20MB 量化 `Depth-Anything-V2-Small`，在用户浏览器利用 WebAssembly/WebGPU 计算 | **$0.00 (完全免费)**<br>端侧耗时 **~150ms** | **零服务器成本、零 API 开销**，在第 1 秒消除所有加载等待感。 |
| **原生姿态虚拟换装 (VTO)** | **FASHN.ai API**<br>(平替: Fal.ai CatVTON API) | `/backend` 调用 `POST /v1/run`，输入用户照片与目标单品图，指定 `category` (tops/bottoms) | **$0.02 ~ $0.05 (约 0.14~0.35 元)**<br>耗时 **1.5 ~ 2.5s** | 工业级保持面部、发型、体态与未替换裤鞋，自然生成布料褶皱与光影。 |
| **360° 关键帧生成** | **Fal.ai SV3D / Era3D API**<br>(平替: 可灵 AI Camera Orbit) | `/backend` 输入换装后的 2D 图，请求定向生成 16 正交角度图，后端轻量脚本拼接为 WebP Sprite Sheet | **$0.06 ~ $0.08 (约 0.42~0.56 元)**<br>耗时 **4.0 ~ 6.0s** | 0° 绝对锚定原图，从数学上杜绝 360 度首尾跳帧。仅在用户确认保存搭配时按需调用。 |

## 4. 端侧渲染与交互播放器选型：Canvas 2D + Sprite Sheet

1. **彻底否定 MP4 手势 Seek**：
   在 iOS Safari / Android WebView 中，对 `<video>` 频繁触发 `currentTime` 会导致解码器重置、丢帧排队与黑屏卡死，属于公认的工程陷阱。
2. **确认 WebP Sprite Sheet + Canvas 2D 方案**：
   - 后端下发 16 关键帧拼接好的单个 4×4 WebP 网格大图（体积约 1.1MB）；
   - 前端 Canvas 单次解码，常驻显存仅约 12MB；
   - 监听手势位移取模换算切片行列，通过 `ctx.drawImage` 局部 Blit，实现**零 I/O 调度、真机稳定 60fps 丝滑拖拽**。

## 5. 架构边界与前后端契约

- **Go 后端（`/backend`）**：
  - 封装所有第三方商业 API 调用（隐藏凭证，控制账单）；
  - 编排业务实体与数据持久化（PostgreSQL 记录 WardrobeItem 与 Look）；
  - Huma 自动生成并暴露 `/openapi.json`。
- **Next.js 前端（`frontend`）**：
  - 运行 `npm run openapi`（基于 `@umijs/openapi`）一键自动同步生成强类型 Axios 客户端；
  - 组合 `shadcn/ui` 与 Canvas 2D 展台，实现黑白克制的无边框视觉体系。
