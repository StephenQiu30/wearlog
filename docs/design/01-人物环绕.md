# 人物环绕与立体数字衣橱系统设计 (Vercel & Google Go 双规范落地版)

## 1. 依据与核心设计决定

采用 [REQ-01](../requirement/01-人物环绕.md) revision 3、[RES-01](../research/01-人物环绕.md) revision 3。
本设计旨在 1:1 复刻 Woo 立体数字衣橱，并严格贯彻两项工业级工程标准：
* **前端工程**：严格遵循 **Vercel 设计规范与 Next.js App Router 最佳实践**（Geist 视觉体系、Server-First 架构、零累积布局偏移 CLS=0、非阻塞水合）；
* **后端工程**：严格遵循 **Google Go Style Guide（Google Go 设计规范）**（接口隔离、Context 显式传播、显式错误包裹、无包级可变状态、并发生命周期控制）。

### 核心架构原则（避免过度设计）
1. **纯 API 编排，零 GPU 运维负担**：
   后端不自建任何 PyTorch/显卡进程，所有视觉与模型推理通过商业/Serverless API（Gemini 2.0 Flash、Fal.ai / FASHN.ai、Fal.ai SV3D）完成，空闲成本为 0；
2. **前后端全类型契约自动同步**：
   后端通过 Huma 导出标准 `/openapi.json`，前端通过 `npm run openapi`（`@umijs/openapi`）自动生成强类型 Axios 客户端，100% 编译期类型安全；
3. **分级体验与端侧零成本计算**：
   - 2.5D 深度视差由前端 `onnxruntime-web` 在用户浏览器本地运行，服务器算力成本为 0，300ms 内消除等待感；
   - 360° 交互由 **Canvas 2D + 16 关键帧 WebP Sprite Sheet** 实现，常驻显存仅约 12MB，真机稳定 60fps。

## 3. 后端工程设计规范 (遵循 Google Go Style Guide)

后端代码落位在 `wearlog-server/backend`，必须严格落实 Google 官方 Go 编码指南：

### 3.1 包结构与单一职责 (`package orbit`)
* **包路径与命名**：
  * 领域层：`internal/application/orbit/`（`package orbit`）
  * 适配层：`internal/adapter/httpapi/orbit_*`（`package httpapi`）
* **包设计守则**：
  * 禁止创建泛化的 `util`、`common`、`helper` 包；
  * 包级禁止存在可变的全局变量（无全局 Client、无全局缓存 Map），所有状态由实例持有。

### 3.2 接收者与命名规范 (Receiver & Method Naming)
* **短小且一致的接收者命名**：
  ```go
  // 正确：1~2 个字母，全包保持完全一致
  func (s *Service) AnalyzeOutfit(ctx context.Context, ...) (...)
  func (h *OrbitHandler) handleAnalyze(ctx context.Context, ...) (...)
  
  // 严格禁止：使用 this, self 或冗长名字
  ```

### 3.3 Context 传播与生命周期 (Context-First)
* 所有涉及 I/O、数据库操作或外部 API 调用的函数，`ctx context.Context` 必须作为**第一个参数**传递；
* **严禁将 Context 存入结构体内部**；
* 针对外部 API 调用，必须通过 `context.WithTimeout` 绑定超时预算：
  ```go
  ctx, cancel := context.WithTimeout(ctx, 25*time.Second)
  defer cancel()
  ```

### 3.4 显式错误处理与包裹规范 (Error Handling)
* 错误必须显式处理，严禁忽略；
* 使用 `%w` 进行错误包裹，携带明确的领域上下文；
* **错误字符串必须小写，且末尾不得带标点符号**：
  ```go
  // 正确
  if err != nil {
      return nil, fmt.Errorf("orbit: failed to call gemini api: %w", err)
  }
  
  // 错误示范：大写开头、末尾带句号、忽略错误
  // return nil, fmt.Errorf("Orbit: Failed to call Gemini API.")
  ```

### 3.5 接口隔离与面向接口消费 (Interface Segregation)
* 遵循“**接收接口，返回具体结构体**（Accept interfaces, return structs）”原则；
* 接口定义在**调用方**（consumer package），保持小而专一（1~3 个方法）：
  ```go
  // internal/application/orbit/ports.go
  package orbit
  
  type FashionAnalyzer interface {
      AnalyzeStyle(ctx context.Context, imageURL string) (*StyleAnalysis, error)
  }
  
  type MattingProvider interface {
      ExtractGarments(ctx context.Context, imageURL string) ([]ExtractedGarment, error)
  }
  
  type TryOnProvider interface {
      ExecuteTryOn(ctx context.Context, req TryOnRequest) (string, error)
  }
  
  type OrbitGenerator interface {
      Generate16Keyframes(ctx context.Context, imageURL string) ([]byte, error)
  }
  ```

### 3.6 并发控制与 Goroutine 生命周期
* 外部并行调用（如同时调用 Gemini 分析与 Fal.ai 抠图）必须使用 `golang.org/x/sync/errgroup` 配合上下文取消，**杜绝 Goroutine 泄漏**：
  ```go
  g, ctx := errgroup.WithContext(ctx)
  
  g.Go(func() error {
      analysis, err := s.analyzer.AnalyzeStyle(ctx, req.ImageURL)
      if err != nil {
          return fmt.Errorf("orbit: style analysis failed: %w", err)
      }
      res.Analysis = analysis
      return nil
  })
  
  g.Go(func() error {
      garments, err := s.matting.ExtractGarments(ctx, req.ImageURL)
      if err != nil {
          return fmt.Errorf("orbit: garment matting failed: %w", err)
      }
      res.Garments = garments
      return nil
  })
  
  if err := g.Wait(); err != nil {
      return nil, err
  }
  ```

### 3.7 Huma 接口操作与结构体 Tag 规范
在 `internal/adapter/httpapi/orbit_contract.go` 中精确定义 Huma 输入输出：
```go
package httpapi

type AnalyzeOutfitRequest struct {
    RawBody struct {
        ImageURL string `json:"image_url" required:"true" format:"uri" doc:"用户全身穿搭照的私有访问地址"`
    }
}

type AnalyzeOutfitResponse struct {
    Body struct {
        PersonID          string            `json:"person_id" doc:"用户体态基准 ID"`
        FrontImageURL     string            `json:"front_image_url" doc:"标准化背景后的正向原图"`
        SeasonTags        []string          `json:"season_tags" doc:"适宜季节 (如 Autumn, Spring)"`
        TempRange         string            `json:"temp_range" doc:"适宜温度区间 (如 16℃~23℃)"`
        StyleTags         []string          `json:"style_tags" doc:"穿搭风格定义 (如 Cleanfit)"`
        ExtractedGarments []GarmentItemDTO  `json:"extracted_garments" doc:"拆解出的单品列表"`
    }
}
```

## 4. 前端工程设计规范 (遵循 Vercel Next.js / Geist 规范)

前端代码落位在 `wearlog-server/frontend`，严格遵守 Vercel 性能与设计系统标准：

### 4.1 服务端与客户端组件边界 (Server-First, Client-Leaf)
* **默认 Server Component (`RSC`)**：
  * 页面路由 `src/app/(site)/fitting-room/page.tsx` 与框架容器保持为 Server Component，负责数据预取与初始 HTML 直出；
* **下沉 `"use client"` 到叶子节点**：
  * 仅交互密集型控件使用客户端组件：
    * `SpriteSheetScrubber.tsx`（纯 Canvas 触摸事件）
    * `ParallaxCanvas.tsx`（本地深度视差着色器）
    * `GarmentDock.tsx`（横滑选择状态）

### 4.2 零累积布局偏移 (Cumulative Layout Shift, CLS = 0)
* 人物展台必须包裹在具有**严格固定纵横比**的容器中，杜绝图片加载完成瞬间产生页面抖动：
  ```tsx
  <div className="relative aspect-[3/4] w-full max-w-[420px] overflow-hidden rounded-xl bg-muted/30">
    {/* Canvas 绝对定位于其中 */}
  </div>
  ```

### 4.3 非阻塞水合与大型依赖懒加载
* `onnxruntime-web`（体积约 20MB）**绝对不能直接打包进首屏主 bundle**；
* 必须通过异步 `import()` 或 `next/dynamic` 在用户首屏进入后再按需动态载入，保证 Lighthouse 性能评分 ≥ 95：
  ```typescript
  // 仅在浏览器端挂载且视口可见后懒加载
  useEffect(() => {
    let ort: typeof import("onnxruntime-web") | null = null;
    async function init() {
      ort = await import("onnxruntime-web");
      // 初始化会话
    }
    init();
  }, []);
  ```

### 4.4 Vercel Geist 视觉体系与“高级感”落地
* **色彩映射与无边框表面**：
  * 画布底色：`#fafafa`（`bg-background`）；
  * 移除所有厚重实体卡片描边与阴影，仅用留白和明度层次分割区域；
* **脚底接地基线（Foot Baseline）强制锁定**：
  * 画布高度 Y 轴 88% 处设为接地水平线，所有正面图、换装图和 16 视角图，脚跟位置强对齐此线，彻底避免换装时“人物上下跳动”；
* **柔和接触阴影（Contact Shadow）**：
  * 在脚底生成一层半透明、横向羽化的环境光遮蔽阴影（`rgba(0,0,0,0.12)`），避免人像浮空。

### 4.5 Canvas 2D 极速切片 Blit 算法
```typescript
// 60fps 稳定手势拖拽算法 (显存仅占 ~12MB)
export function renderSpriteFrame(
  ctx: CanvasRenderingContext2D,
  sheet: HTMLImageElement,
  frameIndex: number, // 0 ~ 15
  canvasW: number,
  canvasH: number
) {
  const col = frameIndex % 4;
  const row = Math.floor(frameIndex / 4);
  const frameW = sheet.naturalWidth / 4;
  const frameH = sheet.naturalHeight / 4;

  ctx.clearRect(0, 0, canvasW, canvasH);
  ctx.drawImage(
    sheet,
    col * frameW, row * frameH, frameW, frameH, // 源切片坐标
    0, 0, canvasW, canvasH                      // 目标画布坐标
  );
}
```

### 4.6 辅助功能与无障碍 (a11y)
* 拖拽不是唯一交互途径：展台底部提供“正向 (0°)”、“侧面 (90°)”、“背面 (180°)”等快捷 `Button`；
* 严格应用 `radix-ui` 的键盘导航，焦点环通过 `focus-visible:ring-2 focus-visible:ring-foreground` 保持清晰可见；
* 系统开启 `prefers-reduced-motion` 时，自动关闭惯性旋转与视差动画。

## 6. 质量、超时与容灾红线

1. **25 秒全链路熔断**：任何外部 API（VTON 试穿或 360 关键帧扩散）超过 25s 自动超时中断，释放连接，前端平滑维持 2.5D 静态立体图，绝不让用户无限等待；
2. **前后端接口同步卡点**：每次后端修改 Huma Contract，必须运行 `go test ./...` 保证 `/openapi.json` 生成正确，且前端必须运行 `npm run openapi` 保证 TypeScript 零报错；
3. **敏感凭证防泄漏**：Gemini API Key 与 Fal.ai / FASHN.ai 密钥严格由 Go 后端通过环境变量读取，禁止在前端代码或公开 HTTP 请求中透传。
