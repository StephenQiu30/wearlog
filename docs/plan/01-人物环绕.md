# 人物环绕与立体数字衣橱实施计划 (纯 API 与前后端契约版)

## 1. 规格与执行边界

采用 [REQ-01](../requirement/01-人物环绕.md) revision 3、[DES-01](../design/01-人物环绕.md) revision 3、[PRD-01](../prd/01-人物环绕.md) revision 3、[RES-01](../research/01-人物环绕.md) revision 3。

本计划落实**“零自建算力、纯 API 组装、前后端全类型契约”**的实施步骤，代码落点严格限定在 `wearlog-server/backend` 与 `wearlog-server/frontend`。

## 2. 实施任务与代码路径分解

| 任务编号 | 任务名称与目标 | 对应 AC / 规格 | 准确代码落点与产出物 | 依赖与验证方式 |
| --- | --- | --- | --- | --- |
| **T-01** | API 凭证与协议配置 | AC-01～AC-09 前提 | `backend/internal/bootstrap/` 增加外部 API 配置项（Gemini API Key、Fal.ai / FASHN.ai Key） | 验证外部 HTTP API 连通性，不写产品代码 |
| **T-02** | Go 后端 Orbit 模块与 Huma 路由 | AC-03、AC-04、AC-05 | `backend/internal/application/orbit/`<br>`backend/internal/adapter/httpapi/orbit_routes.go`<br>`backend/internal/adapter/httpapi/orbit_contract.go`<br>`backend/internal/adapter/httpapi/orbit_handlers.go` | 启动后端服务，校验 `/openapi.json` 包含 3 个核心路由 |
| **T-03** | 前端 OpenAPI 强类型代码生成 | AC-07 | 运行 `npm run openapi`，自动生成 `frontend/src/api/orbit.ts` 及相关 TypeScript DTO | 检查 TypeScript 编译通过，无手动手写类型 |

## 3. 验收与回退红线

1. 服务端禁止引入任何本地 Python 推理服务或 GPU 容器依赖；
2. 任何外部第三方 API 响应超过 25s 必须自动触发熔断，降级保留静态 2.5D 深度视差；
3. 前后端交互必须严格通过 `openapi2ts` 自动生成的 SDK，禁止手写重复接口请求函数。
